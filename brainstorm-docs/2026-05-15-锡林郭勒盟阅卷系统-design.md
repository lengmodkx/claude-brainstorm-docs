**版本：** V1.0

**日期：** 2026-05-15

**状态：** 已确认

---

## 1. 项目概述

### 1.1 项目背景

解决当前锡林郭勒盟全盟统考各学校考试安排冲突、报名信息混乱、阅卷效率低、阅卷平台年限老旧、人工参与度高、操作人员专业要求高等问题。

### 1.2 项目规模

- **覆盖范围：** 72所小学、31所中学、21所高中，近10万学生
- **考试频次：** 年均考试累计10次左右，累计12万考生
- **特殊需求：** 部分学校分国家通用语言授课和原民族语言授课

### 1.3 建设目标

构建覆盖"考前-考中-考后"全流程的数字化平台，实现：
- 考务管理无纸化
- 报名数据标准化
- 阅卷流程电子化
- 成绩分析智能化

## 5. 核心模块设计

### 5.1 考务管理模块

**功能清单：**
- 考试日历管理（创建学年/学期考试计划，按周/月视图展示）
- 考点与考场设置（按学校/校区配置标准化考点）
- 考场编排（按班级/按考号/随机混编，生成考场分布图）
- 监考排班（自动/手动分配监考教师，冲突检测）
- 考务材料管理（考务手册、考场记录单、考生签到表等模板）

### 5.2 报名管理模块

**功能清单：**
- 报名资格管理（导入学籍库，设置报名资格校验规则）
- 在线填报（考生登录后填写信息、上传照片、选择报考科目）
- 审核与缴费（班主任/学校管理员在线审核，对接第三方支付）
- 数据汇总（实时统计各校报名人数、缺报科目）
- 考号生成（按规则自动生成：年份+考区+学校+考场+座位）

### 5.3 阅卷管理模块（核心）

**阅卷流程：**

```
答题卡扫描 → 图像识别 → 客观题自动评分 → 主观题切割 → 任务分发 → 教师批阅 → 成绩合成
```

**答题卡扫描：**
- 提供标准 HTTP 接口，扫描仪调用接口上传图片
- 自动识别条形码（考号）、切割正反面、A/B卷区分
- 异常检测：空白卷、损坏卷、雷同卷标记

**主观题切割分发：**
- 按题号切割主观题区域
- 图片加密传输（防止泄密）
- 任务预分配：开考前按学科/题号切好任务池

**多评机制：**
- 一评：教师A批阅 → 完成
- 双评：教师A一评 → 教师B二评 → 差值超限 → 三评/仲裁
- 仲裁：差值超限 → 题组长仲裁

**阅卷任务分发策略：**
- 预分配方案（最省事儿）：
  - 开考前按学科/题号切分任务池
  - 按阅卷教师数量均匀分配（每人一批任务）
  - 老师报到 → 直接领任务 → 开始批阅 → 完成后继续领下一批
- 题组长职责：处理异常卷、仲裁，不负责日常任务分配

**异常处理：**
- 空白卷检测
- 答错区域标记
- 雷同卷自动标记
- 切割错位、试卷旋转处理

### 5.4 成绩管理模块

**成绩合成：**
- 客观题（系统自动）+ 主观题（教师打分）= 总分
- 支持缺考标记、违纪扣分、听力免试加分
- 支持"单科不纳入总分"配置

**成绩复核：**
- 考生在线提交复核申请（限查是否漏评、漏统）
- 管理员在线反馈复核结果

**多维分析报表：**

| 维度 | 内容 |
|------|------|
| 学生级 | 单科/总分排名（可设置仅百分比）、进退步对比、小题得分率 |
| 班级/校级 | 平均分、优秀率、及格率、低分率、分数段分布、标准差 |
| 区级 | 学校横向对比、学业质量监测报告（自动生成Word/PDF） |

**成绩发布：**
- 支持按学校/班级分批发布
- 设置查分密码锁
- 生成《学生个人成绩单》（含学科诊断建议）

## 6. 数据架构

### 6.1 数据库设计（PostgreSQL）

```
exam数据库
├── exam_calendar          -- 考试日历
├── exam_arrangement      -- 考点考场安排
├── exam_invigilation      -- 监考排班
├── exam_registration     -- 报名信息
├── exam_subject          -- 科目管理
├── exam_paper            -- 试卷管理
└── exam_material         -- 考务材料

scoring数据库
├── scoring_task          -- 阅卷任务
├── scoring_objective     -- 客观题打分
├── scoring_subjective    -- 主观题打分
├── scoring_arbiter      -- 仲裁记录
└── scoring_exception     -- 异常卷记录

result数据库
├── result_student        -- 学生成绩
├── result_analysis       -- 分析报表
├── result_publish        -- 发布记录
└── result_review         -- 复核记录

system数据库
├── sys_user              -- 用户
├── sys_role              -- 角色
├── sys_permission        -- 权限
├── sys_tenant            -- 租户（多租户支持）
└── sys_config            -- 系统配置
```

### 6.2 文件存储架构

```
扫描上传 → 本地缓存 → MinIO存储 → OSS归档

答题卡图片路径：
/scanning/{examId}/{schoolId}/{paperId}/
    ├── 客观题/{uuid}.jpg
    └── 主观题/{uuid}.jpg
```

### 6.3 缓存设计（Redis）

| 缓存内容 | 过期策略 |
|----------|----------|
| 会话信息 | 2小时 |
| 阅卷任务分配状态 | 实时 |
| 成绩查询结果（高峰期） | 5分钟 |
| 考试安排信息 | 1天 |
| 报名资格校验规则 | 1小时 |

**成绩查询优化：**
- 成绩发布时预热 Redis 缓存
- 考生查分先查缓存，缓存未命中再查数据库
- 数据量可控（10万考生 × 10次/年 = 100万条）

## 7. API 架构

### 7.1 API 分层

```
Open API（对外）
├── 学生端API
└── 第三方系统API（学籍系统）

Inner API（内部）
├── 移动端API
└── 管理端API

Service API（服务间）
├── Feign调用
└── 消息队列
```

### 7.2 核心接口

| 模块 | 接口 | 说明 |
|------|------|------|
| 考务 | POST /exam/arrange | 创建考试安排 |
| | GET /exam/venue/{id} | 获取考点信息 |
| | POST /exam/invigilation/assign | 分配监考 |
| 报名 | POST /register | 在线报名 |
| | GET /register/status | 报名状态 |
| | POST /register/audit | 审核报名 |
| 阅卷 | POST /scanning/upload | 扫描上传 |
| | GET /scoring/task | 领取阅卷任务 |
| | POST /scoring/submit | 提交打分 |
| | GET /scoring/progress | 阅卷进度 |
| 成绩 | GET /result/{studentId} | 成绩查询 |
| | POST /result/review | 成绩复核 |
| | GET /report/class | 班级报告 |

### 7.3 API 规范

- RESTful 风格
- 统一响应格式：`{ code, message, data }`
- 鉴权：JWT Token
- 限流：Sentinel

## 8. 非功能性需求

### 8.1 安全性

- 数据加密传输（HTTPS）
- 成绩数据库字段加密存储
- 阅卷期间严格封存成绩，禁止导出
- 操作日志留存至少3年
- 符合等保2.0要求

### 8.2 性能

- 支持1万考生同时查分，页面响应时间 < 2秒
- 阅卷高峰期支持500名教师同时在线批阅
- 客观题自动识别：1万考生答题卡 ≈ 1.5小时（预计）

### 8.3 数据对接

- 与"区域学籍管理系统"对接，同步学生异动数据
- 提供标准API接口，支持第三方扫描仪/阅卷硬件接入

### 8.4 容灾备份

- 每日增量备份，每周全量备份
- 阅卷数据实时同步至备用服务器
- 防止单点故障
